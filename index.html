AUTHENTICATION

토큰 만료 처리를
클라이언트와 서버 실행 환경에 맞췄습니다

공통 HTTP 계층 · 자동 갱신 · 요청 재시도

판단

  • Next.js의 브라우저·서버 요청은 토큰 접근 방식이 다름
  • 컴포넌트마다 인증 오류를 처리하면 정책이 분산

구현

  • fetch 기반 HTTP 클라이언트와 토큰 주입 래퍼 구성
  • HttpOnly 쿠키 기반 인증 처리와 서버 액션 연결
  • 401 응답 시 토큰 갱신 후 원 요청을 한 번 재시도

변화

  • 화면에서 반복하던 통신·인증 처리를 공통 계층으로 이동
01
클라이언트 / 서버 요청실행 환경에 맞는 인증 래퍼 사용
02
401 → 토큰 갱신갱신 실패는 인증 실패로 전달
03
원 요청 재시도재시도를 한 번으로 제한

BUG FIX

파일 업로드 실패를
multipart 헤더 처리에서 해결했습니다

화면 증상을 요청 형식까지 추적한 사례

문제와 원인

  • 참고 자료 업로드 시 서버가 요청 본문을 해석하지 못함
  • 공통 HTTP 계층이 FormData에도 Content-Type을 지정
  • 브라우저가 생성해야 할 multipart boundary 누락

수정

  • FormData 여부를 확인해 Content-Type 헤더 제거
  • 일반 JSON 요청과 파일 요청의 처리 경로 구분

개선 포인트

  • 업로드 화면 대신 공통 전송 계층의 원인 수정
REQUEST FORMAT
if (body instanceof FormData) {
  headers.delete("Content-Type");
}

// 브라우저가 boundary를 포함한
// multipart 헤더를 자동 생성
